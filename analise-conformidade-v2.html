Cinco riscos prioritários

  1. Transporte sem TLS (Crítica): Compose publica API e front-end por HTTP. O cookie JWT é Secure em Production, então o login de navegador no HTTP local não foi validado e a sessão não deve ser transmitida sem TLS.
  2. Backup sem confidencialidade (Alta): HMAC-SHA256 bloqueia adulteração e os dois testes de integração passaram, mas o SQL no ZIP continua sem criptografia AES; acesso à pasta/volume pode revelar dados.
  3. Fluxos privilegiados não exercitados na sessão real (Alta): criação de pedidos, pagamento, estoque e relatórios têm testes front-end com API mockada; não foi usada sessão admin real no navegador nem transação operacional na base persistente.
  4. CSP externa parcialmente ampla (Alta): `connect-src` está explícito e sem curingas, mas outros directives ainda aceitam `https://*.vlibras.gov.br`; o widget remoto e sua compatibilidade real não foram verificados.
  5. Capacidades de entrega/plataforma ausentes (Alta): inventário não encontrou app mobile/PWA nem workflow de deploy cloud/CD; interface responsiva não substitui esses entregáveis caso sejam exigidos.

Evidências e reprodução

Execução realizada nesta reavaliação
  • docker compose down, sem --volumes, seguido de docker compose up -d --build --wait e docker compose ps: SQL Server, API e front-end ficaram saudáveis; db-init concluiu.
  • dotnet test tests/back-end.Tests.csproj com RUN_INTEGRATION_TESTS=1 e BACKUP_TEST_CONNECTION_STRING apontando para master: 49 aprovados, 0 falhas, 0 ignorados. Os testes de backup criam/removem bancos descartáveis e não usam DB_RESTAURANTE.
  • Em front-end/, npm test -- --coverage: 33 testes em 9 arquivos; statements 66,29%, branches 46,97%, funções 55,55%, linhas 67,83%.
  • npm run lint: passou sem avisos/erros. npm run build: type-check e build passaram; maior chunk 398,53 kB. npm audit: 0 vulnerabilidades.
  • Endpoints com curl: /api/healthcheck 200; /api/healthcheck/database 200; /api/healthcheck/info 200 com dados: { "status": "ok" }; POST /api/backup/restore sem autenticação 401.
  • Catálogo de DB_RESTAURANTE lido por sys.tables, sys.triggers, sys.procedures, sys.views, sys.objects e sys.indexes: 12 tabelas, 3 triggers habilitadas, 3 procedures, 2 views, 0 funções SQL de usuário e 19 índices.
Objetos SQL e uso encontrado no código

O catálogo e 02-procedures-views.sql contêm sp_fechar_comanda, sp_relatorio_faturamento, sp_ajustar_estoque, vw_comandas_abertas e vw_produtos_mais_vendidos. A busca de código encontrou uso SQL direto apenas de vw_produtos_mais_vendidos em FaturamentoService.GetProdutosMaisVendidos, exposto por GET /api/faturamento/produtos-mais-vendidos. As outras quatro existem no banco, mas não são invocadas por service; endpoints equivalentes de comanda, relatório/ajuste operam pela lógica EF/service, não pelas procedures/views. A função SQL segue opcional e não foi criada.

Limites e verificações não realizadas

Não foi usada sessão administrativa real no browser para acionar a página de backup ou operações de negócio; para o restore, a integração autenticou com token de teste contra banco descartável. VLibras depende de script externo e não teve disponibilidade funcional confirmada nesta execução. Não houve auditoria visual manual de teclado em todas as telas, medição WCAG de contraste, validação cloud, nem confirmação do relatório final/artefatos externos do PIM. Esses itens foram marcados NÃO VERIFICÁVEL quando a prova era necessária.

O teste npm registrou apenas um aviso informativo do Vite sobre alternar o plugin SWC; o lint passou sem avisos.
