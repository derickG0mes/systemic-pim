Veredito: atende parcialmente

As fases 8–10 entregaram PWA instalável, CD para publicar imagens no GHCR, plano de nuvem e decisões de escopo. A revisão final reexecutou Compose, endpoints, testes, E2E e Gitleaks. Permanecem uma falha de autenticação num cenário .NET de pedido/pagamento e quatro vulnerabilidades npm de baixa severidade; os fluxos E2E administrativos e VLibras remoto não foram verificáveis sem credenciais de teste.

Não foi feito deploy real nem push. Itens explicitamente excluídos em docs/DECISOES_ESCOPO.md ficam fora do denominador; NÃO VERIFICÁVEL não conta como conforme.

Pendências e riscos prioritários

  1. Falha de integração .NET: Order_payment_trigger_updates_total_closes_check_and_releases_table recebeu Unauthorized ao criar pedido, em vez de Created. A suíte final teve 55 aprovados e 1 falha; o efeito da trigger e o fechamento/liberação dessa jornada não foram verificados.
  2. Dependências: npm audit encontrou quatro vulnerabilidades low em dependência transitiva deepmerge (cadeia Workbox/Vite PWA). A correção sugerida exige downgrade breaking; não foi aplicada.
  3. Fluxos E2E privilegiados: quatro cenários de backup, SignalR e VLibras foram ignorados porque E2E_ADMIN_EMAIL/E2E_ADMIN_PASSWORD não estavam configuradas. Não houve tentativa com conta real.
  4. VLibras remoto: a prova da disponibilidade funcional do widget e da origem externa continua não verificável nesta execução.
  5. Entrega cloud: o CD publica imagens após CI, mas não houve publicação remota nem deploy; isso foi deliberadamente excluído do trabalho de validação.

Evidências e reprodução

Execução realizada nesta reavaliação
  • docker compose down, sem remover volumes; docker compose up -d --build --wait e docker compose ps: SQL Server/API/front-end saudáveis; db-init concluiu.
  • Endpoints: healthcheck, database e info retornaram HTTP 200; POST restore sem login retornou 401. O healthcheck não contém versao; seu objeto dados contém o status.
  • CSP obtida com curl -sSI: nenhum wildcard *; resposta HTTP sem HSTS. A diretiva HSTS permanece apenas no bloco HTTPS comentado do nginx.
  • Catálogo SQL somente leitura: 12 tabelas, 3 triggers habilitadas, 3 procedures, 2 views, 0 funções SQL de usuário e 19 índices. A inicialização dos scripts idempotentes concluiu no Compose reconstruído.
  • RUN_INTEGRATION_TESTS=1 dotnet test tests/back-end.Tests.csproj, com connection string apontando para master do SQL Compose local: 55 aprovados, 1 falha, 0 ignorados. Os testes criam bancos com nomes aleatórios e não usam DB_RESTAURANTE como banco de teste.
  • npm test -- --coverage --run: 33/33 testes, 9 arquivos; statements 66,29%, branches 46,97%, funções 55,55%, linhas 67,83%.
  • npm run lint e npm run build: passaram. O chunk de maior tamanho foi 369,31 kB; a build também gerou service worker e precache de 44 arquivos estáticos (~979 KiB).
  • npm audit: terminou com código 1 e 4 vulnerabilidades low. Nenhuma correção forçada foi aplicada.
  • npm run test:e2e: 9 testes encontrados; 5 passaram e 4 foram ignorados por ausência das variáveis de conta admin.
  • Gitleaks, histórico inteiro: primeiro identificou um generic-api-key em fixture de teste; comparação SHA-256 local foi diferente para os segredos disponíveis. Após ignore específico comentado, nova varredura: 119 commits, nenhum achado.
  • Lighthouse PWA em HTTP local: score 1,00; installable-manifest, maskable-icon, splash screen e themed omnibox aprovados.
  • Inventário: 13 controllers, 69 atributos de ações HTTP, zero arquivos .vs rastreados. API e front-end locais mantiveram HTTP e responderam 200.

vw_comandas_abertas, sp_relatorio_faturamento e sp_ajustar_estoque são chamados por DatabaseRoutineQueries; vw_produtos_mais_vendidos continua integrado a FaturamentoService. sp_fechar_comanda continua sem chamada porque substituir o fluxo existente duplicaria validações e alteraria o caminho de fechamento; não foi trocado. Limites

O workflow CD não pode ser executado por evento de CI na branch remota sem push; nenhum push foi feito. A conta administrativa de E2E não foi disponibilizada. Inclusão social e artefatos acadêmicos do grupo não são verificáveis apenas pelo repositório. O relatório não substitui deploy, avaliação manual ou teste em navegador/dispositivo externo.
